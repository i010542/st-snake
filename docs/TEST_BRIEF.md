# st贪吃蛇测试验收简报

## 1. 验收范围与依据

验收对象是 `st贪吃蛇` Web MVP。规则依据依次为：

1. `docs/DESIGN.md`
2. 本文的可观察验收口径
3. `docs/DEV_BRIEF.md` 中的工程约束

测试不验收后续迭代项，不因缺少音效、皮肤、排行榜或触屏手势判失败。

基线环境：

- 最新稳定版 Chrome 桌面端，使用物理键盘。
- 补充兼容检查：最新版稳定版 Edge、Firefox、Safari（具备相应设备时）。
- 默认干净会话开始；涉及最高分时按用例要求保留或修改站点本地存储。
- 打开开发者工具 Console，并从执行测试前开始保留观察。

## 2. 验收总标准

版本只有同时满足以下条件才可判定 **PASS**：

- 本文全部 P0 和 P1 用例均实际执行并通过；无“未测”项。
- 不存在未关闭的阻断/严重缺陷：无法启动、核心流程中断、规则错误、数据错误、稳定复现的崩溃或控制台未处理异常。
- `npm run build`、`npm run lint`、`npm test` 均以退出码 0 完成，且没有被跳过的 P0 自动化测试。
- Chrome 中至少完成一局“开始 → 移动 → 吃食物 → 暂停/继续 → 死亡 → 重开”的串联流程。
- 验收期间 Console 无未处理异常、React 警告和资源 404。
- 证据满足第 5 节要求，并能对应到版本提交标识和用例编号。

任一 P0 失败，版本直接判 **FAIL**。P1 失败同样不能最终 PASS；可修复后仅回归失败项及其相关 P0，再重新给出结论。不能执行的用例记为 **BLOCKED**，不得按 PASS 处理。

## 3. 固定预期

测试时按以下值判断，不接受“看起来差不多”：

- 棋盘：24 列 × 18 行。
- 初始蛇：3 格，位于棋盘中部，初始向右。
- 逻辑速度：每 125 ms 移动 1 格，即 8 格/秒，不随分数加速。
- 每个食物：蛇长 `+1`，分数 `+10`。
- 食物：同一时刻最多 1 个，只出现在非蛇身格。
- 最高分键：`st-snake.highScore.v1`。
- 方向键和 WASD 均可移动；P/Escape 暂停或继续；菜单和结束状态可用 Enter/Space 操作。

### 4.1 自撞用例补充

TC-008 必须在蛇长至少 5 时执行。原因是长度 4 的蛇走紧凑 U 形时，下一头部可能进入即将腾出的尾格；按照设计这是合法移动，不应误报为自撞。若随机食物使指定路线不安全，可换到空旷区域并旋转整套方向，但必须保证第三次转向后的下一头部命中“不是即将移走的尾格”的身体。

### 4.2 快速连按执行口径

- 优先使用键盘实测并以 60 FPS 或更高帧率短录屏取证。
- 若人工无法稳定在 125 ms 内输入，可用端到端自动化在同一逻辑步内连续派发 `keydown`，但必须同时保留一次人工键盘冒烟结果。
- 自动化不得直接修改 React 状态来伪造 PASS；可以派发真实浏览器键盘事件。

## 5. 证据要求

每次正式验收必须保存：

- **版本证据**：提交 SHA、测试日期、浏览器及版本、操作系统、页面 URL/构建方式。
- **截图**：
  - 菜单/初始状态；
  - 至少一次吃食物后的分数和增长；
  - 撞墙结束及原因；
  - 自撞结束及原因；
  - 刷新后保留的最高分；
  - Console 在完整流程后的无错误状态。
- **短录屏**：
  - 一段串联“开始、移动、吃食物、暂停、继续、死亡、重开”的流程；
  - 一段覆盖 TC-009～TC-012 的禁止反向和快速连按，画面需同时看得到按键提示工具或在记录中注明按键时序。
- **命令记录**：`build`、`lint`、`test` 的原始命令、退出码和结果摘要。
- **用例结果表**：每个编号标记 PASS/FAIL/BLOCKED，并链接对应证据或缺陷编号。

截图只能证明画面当时状态，不能单独证明移动时序；快速连按、暂停冻结和重开流程必须用短录屏或可复核的自动化报告。Console 截图必须来自实际验收页面和同一版本，不能用空白页面代替。

## 6. 缺陷严重度

| 严重度 | 定义 | 示例 |
|---|---|---|
| S0 阻断 | 应用无法启动或无法进入游戏，验收无法继续 | 白屏、构建失败、开始按钮无效 |
| S1 严重 | 核心规则错误、数据丢失或稳定崩溃，无合理绕过 | 能反向掉头、吃食物不增长、碰撞不结束 |
| S2 一般 | 非核心功能或兼容/可访问性不符合，有绕过方式 | Escape 不能暂停但 P 可用、窄屏遮挡 |
| S3 轻微 | 不影响规则和完成流程的表现问题 | 文案对齐、小范围视觉瑕疵 |

最终 PASS 时不得遗留 S0/S1；同时本文要求全部 P1 通过，因此与 P1 直接对应的 S2 也需关闭并回归。
