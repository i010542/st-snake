# st贪吃蛇 Windows 本地版设计与 Cursor 执行说明

## 1. 文档用途

本文用于指导 Cursor 将当前仓库中的浏览器版 `st贪吃蛇` 改造成可安装、可离线运行的 Windows 桌面应用。

本文既是产品设计，也是实施约束。Cursor 应按文末任务顺序逐步完成，不要推翻现有游戏规则，不要重写已经通过测试的游戏核心。

相关基线文档：

- `docs/DESIGN.md`：游戏规则与状态机的唯一依据。
- `docs/DEV_BRIEF.md`：现有 Web 版的模块边界和实现约束。
- `docs/TEST_BRIEF.md`：现有玩法验收标准。
- 本文：Windows 桌面化、界面调整、打包和桌面端验收标准。

发生冲突时，玩法规则以 `DESIGN.md` 为准；桌面运行方式、窗口行为和打包方式以本文为准。

---

## 2. 产品定义

### 2.1 产品名称

- 中文名：`st贪吃蛇`
- 英文内部名：`st-snake`
- Windows 应用标识：`com.i010542.st-snake`
- 默认可执行文件名：`st贪吃蛇.exe`

### 2.2 产品目标

将现有网页游戏包装为轻量、稳定、无需联网的 Windows 桌面小游戏，使用户能够：

1. 通过安装包安装，也可以生成免安装版本。
2. 从开始菜单、桌面快捷方式或可执行文件启动。
3. 在完全断网时正常游玩。
4. 使用键盘完成开始、移动、暂停、继续和重开。
5. 关闭并重新打开应用后，保留最高分、速度、音量和界面偏好。
6. 在常见屏幕缩放比例下获得清晰、居中的游戏画面。

### 2.3 非目标

首个 Windows 版本不包含：

- 在线服务、账号登录、云同步、联网排行榜或自动更新。
- 多人模式、游戏手柄、触屏专用操作。
- 关卡、障碍物、道具、皮肤商店或内购。
- 系统托盘常驻、开机启动、后台运行。
- macOS、Linux 安装包。
- 将游戏重写为原生 WinUI、WPF、Unity 或其他游戏引擎。

## 3. 技术方案

### 3.1 选型结论

使用 **Electron + 现有 React/Vite/TypeScript 应用**。

原因：

- 当前游戏已经由 React、Canvas 和 TypeScript 实现，可以直接复用。
- 不要求用户安装浏览器、Node.js 或其他运行时。
- Cursor 可以在现有仓库内完成主进程、预加载脚本、构建配置和安装包配置。
- 与引入 Rust/Tauri 相比，改造范围更小，首版风险更低。

建议新增依赖：

```text
开发依赖：electron、electron-builder、concurrently、wait-on、cross-env
```

如果当前版本的 Vite 已提供等价的 Electron 开发插件，可以选用一个维护活跃、职责清晰的插件，但不得同时保留两套启动或打包链路。首选显式维护 `electron/main.ts` 和 `electron/preload.ts`，降低隐藏配置。

### 3.2 进程边界

```text
Windows
  └─ Electron 主进程
      ├─ 创建并管理 BrowserWindow
      ├─ 控制菜单、快捷键和退出行为
      └─ 加载预加载脚本
           └─ React 渲染进程
               ├─ 现有游戏状态与规则
               ├─ Canvas 绘制
               ├─ 设置面板
               └─ 本机持久化偏好
```

首版不需要 Node 文件系统能力暴露给 React。最高分和偏好继续使用现有 `localStorage`，Electron 会将其持久化到当前 Windows 用户的应用数据目录。这样可以复用已有存储模块和测试。

### 3.3 安全要求

创建 `BrowserWindow` 时必须满足：

```ts
webPreferences: {
  contextIsolation: true,
  nodeIntegration: false,
  sandbox: true,
  preload: preloadPath,
}
```

其他要求：

- 不启用 `remote` 模块。
- 不在 React 中直接使用 `require`、`fs`、`path` 或 Node 全局变量。
- 生产环境只加载打包后的本地 `index.html`，不能依赖远程 URL。
- 拒绝应用内新窗口、弹窗和未知页面跳转。
- 若未来需要打开外部链接，必须限制为明确允许的 `https:` 地址并调用系统默认浏览器；首版不需要任何外部链接。
- 不申请管理员权限。
- 不读取用户文档、桌面或其他私人目录。

## 4. Windows 应用体验

### 4.1 主窗口

默认窗口建议：

| 项目 | 设计值 |
|---|---|
| 初始内容尺寸 | `960 × 760` |
| 最小尺寸 | `760 × 620` |
| 是否可调整大小 | 是 |
| 是否居中 | 是 |
| 默认背景 | 与应用最外层背景一致，避免启动白闪 |
| 原生标题栏 | 保留 |
| 最大化 | 允许 |
| 全屏 | `F11` 切换 |
| 启动状态 | 首次使用默认尺寸；后续恢复上次窗口尺寸和位置 |

窗口位置恢复时必须检查是否仍落在当前可用显示器区域内。如果用户断开第二块显示器，应用应回到主显示器中央，不能在屏幕外启动。

窗口尺寸和位置可以由主进程写入一个小型 JSON 配置，也可以引入维护良好的窗口状态库。若引入库，只能为解决窗口状态问题，不要加入大型通用状态框架。

### 4.2 原生菜单

使用简洁的中文菜单：

```text
游戏
  新游戏             Ctrl+N
  暂停/继续          P
  退出               Alt+F4

视图
  全屏               F11
  重置缩放           Ctrl+0
  放大               Ctrl++
  缩小               Ctrl+-

帮助
  操作说明           F1
  关于 st贪吃蛇
```

约束：

- “新游戏”“暂停/继续”“操作说明”通过受限 IPC 向页面发送语义事件，不直接操作 React 内部状态。
- 开发者工具只在开发模式下可用，生产安装包不在菜单中暴露。
- 菜单动作必须与页面按钮和键盘快捷键共用同一套状态转换逻辑。

### 4.3 关闭行为

- 点击关闭按钮时直接退出，不缩到托盘。
- 不弹出“是否保存”提示，因为游戏没有未保存文档。
- 进行中的一局不恢复；重新启动回到菜单。
- 最高分和偏好保留。

### 4.4 单实例

应用应使用单实例锁。用户重复启动时：

1. 不创建第二个游戏进程和第二个窗口。
2. 恢复并聚焦已有窗口。
3. 不自动重开当前游戏。

## 5. 视觉设计

### 5.1 设计方向

整体采用“深色桌面街机”风格：克制、清晰、轻量，不使用复杂图片背景或高成本特效。

建议色板：

| 用途 | 颜色 |
|---|---|
| 窗口背景 | `#0B1220` |
| 面板背景 | `#111C2E` |
| 棋盘背景 | `#07111D` |
| 网格线 | `rgba(148, 163, 184, 0.12)` |
| 蛇身 | `#36D399` |
| 蛇头 | `#A7F3D0` |
| 食物 | `#FFB454` |
| 主文字 | `#F8FAFC` |
| 次文字 | `#A7B4C7` |
| 危险/结束 | `#FB7185` |
| 焦点描边 | `#60A5FA` |

颜色必须继续满足 `DESIGN.md` 的对比度和“不只靠颜色表达信息”要求。蛇头使用眼睛、方向缺口或不同形状区分；食物使用圆形和轻微内圈区分。

### 5.2 页面结构

宽窗口布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ st贪吃蛇                     状态：进行中          [设置]    │
├───────────────────────────────────────────┬──────────────────┤
│                                           │  本局分数        │
│                                           │  00120           │
│              24 × 18 棋盘                 │                  │
│              4:3 Canvas                   │  最高分          │
│                                           │  00480           │
│                                           │                  │
│                                           │  速度  8 格/秒   │
├───────────────────────────────────────────┴──────────────────┤
│ 方向键 / WASD 移动    P 或 Esc 暂停    Enter / Space 开始   │
└──────────────────────────────────────────────────────────────┘
```

窄窗口布局（宽度小于约 `840px`）改为上下排列：

```text
标题与状态
分数 / 最高分 / 速度
4:3 棋盘
按键提示
```

要求：

- 游戏棋盘始终保持 `4:3` 比例，不拉伸。
- 棋盘在可用区域中取最大整数或接近整数的格子尺寸，优先保持清晰。
- 界面最小尺寸下不出现横向滚动条。
- 最大化和不同 DPI 下，Canvas 按 `devicePixelRatio` 重绘。
- 页面不能依赖浏览器滚动来看到主要按钮。

### 5.3 状态表现

#### 菜单

- 棋盘可显示静态初始蛇和食物，不能自动移动。
- 棋盘中央出现半透明面板：游戏名、一句话说明、“开始游戏”按钮。
- 操作提示始终可见。

#### 进行中

- 覆盖层消失。
- 右侧或顶部状态区显示本局分数、最高分和速度。
- 状态文本为“进行中”。

#### 暂停

- 棋盘稍微降低亮度，不做模糊以免增加 GPU 开销。
- 中央显示“已暂停”“继续游戏”“重新开始”。
- 明确提示 `P / Esc` 可继续。

#### 游戏结束

- 保留碰撞前最后一个合法局面。
- 中央显示“游戏结束”、死亡原因、本局分数、最高分和“重新开始”。
- 若填满棋盘，则标题改为“胜利”。

### 5.4 动效

- 按钮悬停和按下：`100–160ms`。
- 面板出现：透明度与轻微缩放，最长 `180ms`。
- 吃到食物时允许一次轻量的棋盘闪光或分数跳动，最长 `180ms`。
- 不添加粒子系统、屏幕震动或蛇身插值动画，避免画面位置与逻辑格子不一致。
- 尊重 `prefers-reduced-motion`，开启时取消非必要动效。

## 6. 设置设计

点击“设置”打开应用内模态面板，不创建新窗口。

首版设置项：

| 设置 | 可选值 | 默认值 | 持久化键 |
|---|---|---|---|
| 游戏速度 | `4–15` 格/秒 | `8` | 复用 `st-snake.speedCps.v1` |
| 音效 | 开/关 | 开 | `st-snake.soundEnabled.v1` |
| 音量 | `0–100` | `70` | `st-snake.volume.v1` |
| 显示网格 | 开/关 | 开 | `st-snake.gridVisible.v1` |

设置面板要求：

- 使用原生表单控件或具备完整键盘行为的可访问控件。
- `Esc` 优先关闭设置；设置未打开时才用于暂停/继续。
- 游戏进行中打开设置时自动暂停，关闭设置后保持暂停，由用户主动继续。
- 设置即时生效并安全保存；存储失败不能阻断游戏。
- 提供“恢复默认设置”，只重置设置，不清除最高分。
- 不提供“清除最高分”按钮，以保持与现有 MVP 约束一致。

音效首版只需要三类短音效：吃到食物、游戏结束、按钮确认。资源必须随安装包内置，断网可用；找不到合适的合法资源时，可先使用 Web Audio API 生成简短提示音，不引入来源不明的音频文件。音效不是玩法判定的一部分，自动化测试不可依赖实际扬声器输出。

## 7. 功能与数据规则

桌面版本必须完整保留以下规则：

- 棋盘固定为 `24 × 18`。
- 初始蛇长 3 格，初始方向向右。
- 默认速度 8 格/秒，可调 4–15 格/秒。
- 每个食物增加 10 分和 1 格长度。
- 同一逻辑步只接收第一个合法转向。
- 禁止 180° 直接掉头。
- 支持方向键和 WASD。
- `P / Esc` 暂停或继续；设置面板打开时 `Esc` 先关闭设置。
- `Enter / Space` 在菜单和结束状态开始或重开。
- 暂停时游戏时钟冻结；恢复后不能追帧。
- 最高分保存在本机，低分不能覆盖高分。
- 窗口失去焦点或被最小化时自动暂停，恢复焦点时不自动继续。

桌面菜单的 `Ctrl+N` 新游戏属于明确的重开操作，不需要确认。它必须重置当前分数、蛇、食物、计时器和输入锁，但保留最高分与设置。

## 9. IPC 契约

预加载脚本只暴露下列只读订阅能力：

```ts
type DesktopCommand =
  | 'new-game'
  | 'toggle-pause'
  | 'show-help';

interface DesktopBridge {
  platform: 'win32' | 'darwin' | 'linux';
  onCommand(listener: (command: DesktopCommand) => void): () => void;
}
```

通过 `contextBridge.exposeInMainWorld('desktop', ...)` 暴露，并为 `window.desktop` 添加 TypeScript 声明。

约束：

- 不能暴露通用的 `send(channel, data)` 或 `invoke(channel, data)`。
- 频道名使用固定白名单。
- `onCommand` 必须返回取消订阅函数，React 卸载时调用。
- Web 开发和测试环境中 `window.desktop` 可以不存在；应用必须退化为现有浏览器版且不报错。

## 10. 开发与打包配置

### 10.1 脚本目标

最终 `package.json` 至少提供：

```json
{
  "scripts": {
    "dev": "保留现有 Web 开发命令",
    "dev:desktop": "同时启动 Vite 与 Electron",
    "build": "保留并扩展现有类型检查与 Web 构建",
    "build:desktop": "构建渲染进程、主进程和预加载脚本",
    "dist:win": "生成 Windows 安装包和免安装版本",
    "test": "运行单元与组件测试",
    "test:e2e": "运行 Web 关键流程",
    "test:desktop": "运行 Electron 桌面冒烟测试",
    "lint": "检查全部前端与 Electron TypeScript"
  }
}
```

脚本的实际内容应根据最终构建方案填写，不能保留占位文本。

### 10.2 开发模式

- Vite 先启动本地开发服务器。
- Electron 等待开发服务器可用后再启动。
- 主进程加载开发服务器 URL。
- 关闭 Electron 后，相关开发子进程应一并结束，不能留下后台 Node 进程。
- 页面刷新或热更新不应重复注册桌面命令监听器。

### 10.3 生产模式

- 先执行 TypeScript 检查和 Vite 构建。
- Electron 主进程加载打包后的本地 HTML 文件。
- 所有字体、图标、样式和音效都必须包含在应用包内。
- 断网启动时不能出现请求失败、白屏或长时间等待。

### 10.4 electron-builder 建议

```json
{
  "appId": "com.i010542.st-snake",
  "productName": "st贪吃蛇",
  "asar": true,
  "files": [
    "dist/**/*",
    "dist-electron/**/*",
    "package.json"
  ],
  "win": {
    "target": ["nsis", "portable"],
    "icon": "assets/icon.ico"
  },
  "nsis": {
    "oneClick": false,
    "allowToChangeInstallationDirectory": true,
    "createDesktopShortcut": true,
    "createStartMenuShortcut": true
  }
}
```

具体字段应与安装的 `electron-builder` 版本一致。Cursor 实施时应查阅所安装版本的类型定义或官方文档，不得盲目复制过期配置。

### 10.5 安装产物

发布目录应生成：

- NSIS 安装包：适合普通用户安装与卸载。
- Portable 可执行文件：适合免安装运行。
- 不把未压缩目录、source map、测试文件和开发依赖作为正式交付物。

首版不要求代码签名。未签名安装包可能触发 Windows SmartScreen，README 和发布说明中应如实注明；不要尝试规避系统安全提示。

## 12. 测试策略

### 12.1 必须保留的现有测试

- 所有 `tests/unit/` 规则测试。
- React 组件测试。
- Web 端 Playwright 关键流程。

桌面化不能以删除、跳过或弱化现有测试为代价。

### 12.2 新增单元测试

至少覆盖：

- 设置脏值回退、数值钳制和存储异常。
- 桌面命令订阅与取消订阅。
- 设置打开时自动暂停，关闭后不自动继续。
- 窗口失焦自动暂停事件不会重复切换状态。
- “恢复默认设置”不清除最高分。
- 窗口位置落在已移除显示器时的回退逻辑。

### 12.3 桌面冒烟测试

建议使用 Playwright 的 Electron 支持完成：

1. 启动生产构建后的 Electron 应用。
2. 断言只有一个主窗口。
3. 断言窗口标题为 `st贪吃蛇`。
4. 点击开始游戏，确认状态进入进行中。
5. 使用键盘完成转向和暂停/继续。
6. 触发主菜单“新游戏”，确认局面重置。
7. 打开并关闭设置，确认暂停语义。
8. 关闭窗口，进程在合理时间内退出。

自动化不需要测试 NSIS 安装向导的每一步，但发布前必须人工验证一次全新安装、启动和卸载。

## 14. Cursor 实施顺序

Cursor 应按以下阶段执行。每个阶段结束后先运行相应检查，再继续下一阶段。

### 阶段 1：检查基线

1. 阅读 `README.md`、`docs/DESIGN.md`、`docs/DEV_BRIEF.md`、`docs/TEST_BRIEF.md` 和本文。
2. 阅读现有 `package.json`、游戏状态、输入、循环、存储与主要 UI 文件。
3. 运行现有 `build`、`lint`、`test`，记录基线。
4. 不修改游戏规则来掩盖现有失败；若基线失败，先报告具体失败。

### 阶段 2：加入 Electron 最小外壳

1. 安装必要依赖。
2. 新建主进程和预加载脚本。
3. 实现开发服务器加载与生产本地文件加载。
4. 配置安全的 `BrowserWindow`。
5. 实现单实例、窗口显示和安全退出。
6. 确认现有 Web 模式仍可独立运行。

### 阶段 3：桌面命令和窗口行为

1. 建立严格白名单的 IPC 契约。
2. 实现中文原生菜单。
3. 将菜单命令接入现有 reducer/action，不复制规则。
4. 实现失焦、最小化自动暂停。
5. 实现并验证窗口状态恢复和屏幕外回退。

### 阶段 4：桌面界面优化

1. 按第 5 节完成宽/窄布局。
2. 保持棋盘 4:3 和高 DPI 清晰度。
3. 完成菜单、暂停、结束覆盖层和状态区。
4. 加入设置面板、设置存储和恢复默认设置。
5. 加入轻量音效；不得阻塞游戏主循环。
6. 检查键盘焦点、ARIA 文本和 reduced motion。

### 阶段 5：打包

1. 准备原创应用图标和 `.ico`。
2. 配置 `electron-builder`。
3. 生成 NSIS 与 Portable 产物。
4. 确认正式包不加载开发服务器、不依赖网络、不包含开发菜单。
5. 更新 `.gitignore` 与 `README.md` 的开发、构建、安装说明。

### 阶段 6：测试与交付

1. 补齐设置、IPC、窗口状态和桌面冒烟测试。
2. 运行全部构建、lint、单元、Web E2E 和桌面测试。
3. 在 Windows 10/11 可用环境完成安装、Portable、离线和卸载人工检查。
4. 输出变更摘要、测试结果、已知限制和安装包路径。

## 15. Cursor 工作约束

将以下约束视为不可省略：

1. **先读后改**：先理解现有状态机和测试，禁止把规则重新塞进 React 组件。
2. **小步提交**：按阶段组织改动；每个阶段保持可构建、可测试。
3. **兼容 Web**：`npm run dev` 仍能作为浏览器版运行，`window.desktop` 缺失时不能崩溃。
4. **禁止削弱安全**：不得为了省事启用 `nodeIntegration` 或关闭 `contextIsolation`、`sandbox`。
5. **禁止跳过测试**：不得删除失败测试、加入 `.skip`、`.only` 或降低 TypeScript strict。
6. **禁止无关扩展**：不增加账号、网络、自动更新、排行榜、关卡和复杂动画。
7. **保护用户文件**：应用只能写自己的用户数据目录，不读取或修改其他个人文件。
8. **记录依赖理由**：新增每个运行时依赖前说明用途，能用现有能力完成时不引入库。
9. **遇到歧义先保守实现**：保持现有玩法和数据，不自行改变默认速度、棋盘尺寸或计分。
10. **交付真实结果**：无法执行的 Windows 测试标记为未验证，不得声称通过。
