# st贪吃蛇总体设计

## 1. 文档目的

本文是 `st贪吃蛇` MVP 的唯一总体设计基线，供 st程序员实现、st测试员验收。若实现与本文冲突，以本文及同步更新后的 `DEV_BRIEF.md`、`TEST_BRIEF.md` 为准。

## 2. 产品目标与非目标

### 2.1 产品目标

- 提供一个无需登录、打开浏览器即可游玩的经典贪吃蛇。
- 操作反馈清晰，规则确定；同一输入序列在可控随机数下得到一致结果。
- 覆盖开始、移动、吃食物、成长、计分、暂停、死亡和重开这一完整闭环。
- 在主流桌面浏览器中流畅运行，并为后续增加难度、触屏操作和视觉主题保留模块边界。

### 2.2 非目标（Out of Scope）

MVP 不包含：

- 用户账号、联网后端、云存档、排行榜和多人模式。
- 关卡、障碍物、道具、技能、皮肤商店和音效系统。
- 可穿墙、AI 蛇、地图编辑器或剧情。
- 服务端渲染、SEO、数据分析和广告。
- 对老旧浏览器、游戏手柄或屏幕阅读器完整游玩的保证。
- 随时间加速或可配置棋盘；MVP 采用固定速度和固定棋盘。

## 3. 用户故事

1. 作为首次玩家，我能在菜单中看到操作说明，并用明确的开始按钮或键盘开始游戏。
2. 作为玩家，我能用方向键或 WASD 控制蛇移动，且不会因误按相反方向立即掉头死亡。
3. 作为玩家，我吃到食物后能看到蛇增长一格、分数增加，并看到新食物出现在空格。
4. 作为玩家，我撞墙或撞到自己时能明确知道游戏结束、最终分数和死亡原因。
5. 作为玩家，我能暂停并继续游戏，暂停期间棋盘不发生变化。
6. 作为玩家，我能在游戏结束后快速重开一局，并保留本机最高分。

## 4. MVP 玩法规则

### 4.1 棋盘和初始状态

- 棋盘为 `24 列 × 18 行` 的离散网格。
- 坐标原点 `(0, 0)` 在左上角，`x` 向右增加，`y` 向下增加；合法范围为 `0 ≤ x < 24`、`0 ≤ y < 18`。
- 开局蛇长 3 格，依次为头 `(12, 9)`、身体 `(11, 9)`、尾 `(10, 9)`，初始方向向右。
- 棋盘始终最多存在 1 个食物。开始新局时，食物随机生成在不被蛇占用的格子。
- 初始分数为 0。逻辑步长固定为 `125 ms`，即每秒移动 8 格；MVP 不随分数加速。

### 4.2 移动与输入生效

- 仅在“进行中”状态，每个逻辑步将蛇头向当前方向移动一格。
- 合法转向在下一逻辑步生效，不在按键事件中直接移动蛇。
- 每两个逻辑步之间最多接收第一个合法转向。后续方向按键忽略，直到下一逻辑步完成，防止一次逻辑步内通过连续按键实现 180° 掉头。
- 与该逻辑步起始移动方向相反的输入非法并忽略；非法输入不占用本步的合法转向名额。
- 与当前方向相同的输入是无操作并忽略，也不占用本步的合法转向名额；只有垂直于当前方向的转向会锁定本步输入。
- 示例：当前向右，在同一逻辑步前快速按“上、左”，只接收“上”，忽略“左”；下一步蛇向上移动，而不会向左反向。

### 4.3 吃食物、生长与食物生成

- 当下一蛇头坐标等于食物坐标时，本步吃到食物。
- 吃到食物的本步在头部增加新格且尾部不移除，因此蛇净增长 1 格。
- 每吃一个食物，当前分数增加 10 分。
- 吃到食物后，立即从所有未被蛇占用的格子中等概率选择一个作为新食物。
- 若蛇已占满棋盘，无法生成食物，则本局以“胜利/填满棋盘”结束；MVP 仍进入结束状态并显示最终分数，不再生成食物。

### 4.4 碰撞

- **撞墙**：下一蛇头超出合法坐标范围，本局立即结束，蛇身和分数停留在碰撞前最后一个合法状态。
- **撞自己**：下一蛇头与本步移动后仍会保留的任一蛇身格重合，本局立即结束。
- 普通移动时尾格会在本步移除，因此允许蛇头进入“当前尾格”；吃食物时尾格不移除，但食物不会生成在蛇身上。
- 碰撞步不增加蛇头、不移除尾部、不得分，也不生成新食物。

### 4.5 结束、暂停与重开

- 死亡后显示“游戏结束”、死亡原因（撞墙或撞到自己）、本局分数、最高分和“重新开始”操作。
- 填满棋盘时显示“胜利”、本局分数、最高分和“重新开始”操作。
- 新纪录在本局结束时写入本地最高分；也允许在得分时同步写入，但 UI 结果必须一致。
- 进行中可暂停；暂停期间逻辑时钟冻结，蛇、食物和分数均不变化。恢复后从完整的 `125 ms` 逻辑间隔开始，不能因累计时间立即连走多步。
- 重开会重置蛇、方向、食物、当前分数、计时器和输入锁，但保留最高分。

## 5. 技术选型与理由

### 5.1 建议技术栈

- **语言：TypeScript（开启 strict）**
  游戏状态和方向约束适合静态类型；纯逻辑接口可被单元测试直接调用，减少坐标和状态拼写错误。
- **框架：React + Vite**
  React 负责菜单、计分板、按钮和状态切换；Vite 配置轻、启动快，适合单页纯前端游戏。MVP 不需要 Next.js 的服务端能力。
- **渲染：HTML Canvas 2D**
  棋盘内容是高频、规则的网格绘制，Canvas 比维护数百个 DOM 单元更直接。菜单、分数和按钮仍使用语义化 HTML，以保留可访问性。
- **测试：Vitest + Testing Library；端到端测试可用 Playwright**
  Vitest 与 Vite/TypeScript 配套，纯游戏逻辑可快速测试；Testing Library 验证 UI 状态，Playwright 适合关键键盘流程。
- **样式：普通 CSS/CSS Modules（二选一后统一）**
  页面规模小，不引入额外组件库或 CSS 框架，控制依赖和实现复杂度。
- **持久化：浏览器 `localStorage`**
  MVP 仅保存单个最高分，无需后端。

### 5.2 支持环境

- 验收基线：最新版稳定版 Chrome 桌面端。
- 兼容目标：最新版稳定版 Edge、Firefox、Safari。
- 视口目标：宽度 `≥ 320 px` 时页面不横向溢出；MVP 的正式操控验收以物理键盘为准。

### 5.3 目录结构建议

```text
src/

    GameScreen.tsx
  game/
    constants.ts
    types.ts
    state.ts
```

`game/` 不依赖 React、Canvas 或浏览器存储；其纯函数接收状态并返回新状态。UI 通过命令调用状态层，渲染层只读取状态。

## 6. 模块划分与职责

| 模块 | 职责 | 不负责 |
|---|---|---|
| 输入 `input` | 键位映射、状态相关快捷键、转向合法性和单步输入锁 | 直接修改蛇坐标 |
| 游戏循环 `loop` | `requestAnimationFrame` 调度、固定步长累计、暂停/恢复时钟清理 | 决定碰撞规则 |
| 蛇/移动 `movement` | 根据方向计算下一头部，执行增长或移尾 | 随机生成食物、绘图 |
| 食物 `food` | 枚举空格、用注入的随机源选择食物 | 直接计分 |
| 碰撞 `collision` | 判断越界、自撞及死亡原因 | 展示结束弹层 |
| 状态 `state/reducer` | 创建新局、执行逻辑步、状态转换、计分，维护不可变状态 | DOM/Canvas 操作 |
| 渲染 `render` | 按当前状态绘制背景、网格、蛇、食物；适配 DPR | 改变游戏状态 |
| 存储 `storage` | 安全读取/写入最高分，处理不可用或脏数据 | 保存整局进度 |
| React UI `app` | 菜单、分数、提示、按钮、焦点管理，连接输入/循环/渲染 | 重复实现游戏规则 |

## 7. 数据模型

建议核心类型如下：

```ts
type GamePhase = 'menu' | 'running' | 'paused' | 'gameOver';
type Direction = 'up' | 'down' | 'left' | 'right';
type EndReason = 'wall' | 'self' | 'boardFilled' | null;

interface Point {
  x: number;
  y: number;
}

interface BoardConfig {
  columns: 24;
  rows: 18;
  stepMs: 125;
  pointsPerFood: 10;
}

interface Snake {
  // 索引 0 永远是蛇头；坐标不得重复
  segments: Point[];
  direction: Direction;
  // null 表示本逻辑步尚未接收合法转向
  pendingDirection: Direction | null;
}

interface GameState {
  phase: GamePhase;
  board: BoardConfig;
  snake: Snake;
  food: Point | null;
  score: number;
  highScore: number;
  endReason: EndReason;
}
```

关键不变量：

- `snake.segments.length ≥ 3`，索引 0 为头。
- 除碰撞候选坐标外，已提交到状态中的蛇坐标都在棋盘内且互不重复。
- `food` 若非 `null`，必须在棋盘内且不与蛇重合。
- `score ≥ 0` 且为 10 的整数倍；`highScore ≥ score` 仅在最高分实时更新方案中成立，否则结束前允许 `highScore < score`。
- 仅 `running` 状态执行逻辑步；`gameOver` 必须有非空 `endReason`。

## 8. 状态机

```text
menu --START--> running
running --PAUSE--> paused
paused --RESUME--> running
running --COLLISION / BOARD_FILLED--> gameOver
gameOver --RESTART--> running
paused --RESTART--> running
```

状态行为：

| 当前状态 | 接受的主要事件 | 结果 |
|---|---|---|
| 菜单 `menu` | 开始按钮、Enter、Space | 创建新局并进入 `running` |
| 进行中 `running` | 方向键/WASD | 缓存首个合法转向 |
| 进行中 `running` | P、Escape、暂停按钮 | 进入 `paused` 并清空时间累计 |
| 进行中 `running` | 碰撞/填满棋盘 | 进入 `gameOver` |
| 暂停 `paused` | P、Escape、继续按钮 | 进入 `running`，计时重新起算 |
| 暂停 `paused` | 重新开始按钮 | 创建新局并进入 `running` |
| 结束 `gameOver` | Enter、Space、重新开始按钮 | 创建新局并进入 `running` |

菜单、暂停、结束状态下的方向输入不得改变蛇的方向。浏览器标签页进入后台时应自动进入 `paused`；回到前台后由玩家手动继续，避免后台累计步数。

## 9. 键盘映射与 180° 规则

| 动作 | 主按键 | 备用按键 | 生效状态 |
|---|---|---|---|
| 上移 | ArrowUp | W / w | `running` |
| 下移 | ArrowDown | S / s | `running` |
| 左移 | ArrowLeft | A / a | `running` |
| 右移 | ArrowRight | D / d | `running` |
| 暂停/继续 | P / p | Escape | `running` / `paused` |
| 开始/重开 | Enter | Space | `menu` / `gameOver` |

- 相反方向对：上/下、左/右。
- 合法性必须对“当前逻辑步起始方向 `snake.direction`”判断，而不是对刚写入的 `pendingDirection` 判断。
- 与当前方向相同的输入和相反方向输入都不写入 `pendingDirection`；前者是无操作，后者是非法反向。
- 首个合法方向写入 `pendingDirection` 后，本步方向输入锁定；逻辑步开始时应用它，移动完成后清空，才允许接收下一次转向。
- 方向键和 Space 仅在游戏控件生效场景调用 `preventDefault()`，避免页面滚动；按钮拥有焦点时 Space 保留原生按钮激活语义。
- `KeyboardEvent.repeat` 的方向输入按普通输入处理，但受单步输入锁限制；P/Enter/Space 的重复事件应忽略，避免连续切换状态或重复开局。

## 10. 游戏循环与渲染

- 使用 `requestAnimationFrame` 驱动外层循环，目标渲染帧率为显示器刷新率，基准为 60 FPS。
- 使用固定逻辑步 `125 ms`，不能按渲染帧数移动蛇。
- 每帧累加经过时间；达到步长时执行逻辑步。为防止标签页恢复后“追帧”，单帧最多执行 2 个逻辑步，超出累计时间丢弃；正常的 `visibilitychange` 会先暂停。
- Canvas CSS 尺寸响应容器变化，内部像素尺寸按 `devicePixelRatio` 缩放以保持清晰；游戏坐标始终使用网格坐标，不使用屏幕像素参与规则判断。
- React 不需要按 60 FPS 重建整个组件树；Canvas 绘制可跟随帧循环，文本 UI 仅在状态或分数改变时更新。

## 11. 非功能要求

### 11.1 性能

- 在验收基线环境、普通笔记本、前台标签页中，动画目标为 60 FPS；不得出现持续可感知卡顿。
- 逻辑速度稳定为 8 格/秒，不因机器刷新率为 60/120 Hz 而改变。
- 单局持续 10 分钟不应出现明显内存持续增长或重复注册键盘/动画监听器。

### 11.2 可访问性最低要求

- 菜单、暂停、继续、重开均提供可聚焦的原生 `<button>`，可用 Tab 和 Enter/Space 操作。
- 页面存在可见的键位说明；焦点样式不可移除。
- 当前分数与最高分使用文本展示，不能只画在 Canvas 内。
- 状态变化提供文本：暂停、游戏结束/胜利及原因；结束消息使用 `role="alert"`，分数变化使用节制的 `aria-live="polite"`。
- Canvas 提供可访问名称和简短替代说明，但 MVP 不承诺仅用屏幕阅读器完成实时游戏。
- 蛇、食物、背景颜色满足至少 3:1 的非文本图形对比度；信息不能仅靠红/绿色区分。

### 11.3 本地存储

- 保存最高分，键名固定为 `st-snake.highScore.v1`，值为十进制非负整数。
- 读取缺失、非数字、负数或非整数值时按 0 处理。
- `localStorage` 读取或写入抛错时游戏仍可正常运行；仅当前页面会话保留最高分，不显示阻断错误。
- 重开不清除最高分。MVP 不提供清除最高分按钮，不保存当前局。

## 12. MVP 与后续迭代

### 12.1 MVP

- 固定 24×18 棋盘、固定 8 格/秒。
- 菜单、进行中、暂停、游戏结束/胜利状态。
- 方向键和 WASD；可靠的禁止 180° 掉头与快速连按处理。
- 单食物、成长、每个食物 10 分。
- 撞墙、自撞、填满棋盘判定。
- 本地最高分。
- Canvas 响应式渲染、基础键盘可访问性。
- 核心规则单元测试和关键流程端到端验收。

### 12.2 后续迭代（不进入 MVP 验收）

- 触屏方向按钮或滑动手势。
- 难度选择、逐步加速和不同棋盘尺寸。
- 音效、静音控制、主题和动画效果。
- 障碍物、特殊食物和关卡。
- 完整的屏幕阅读器替代玩法。
- 可复现的种子随机数、回放和分享。
- 经用户明确授权后的在线排行榜与账号体系。
